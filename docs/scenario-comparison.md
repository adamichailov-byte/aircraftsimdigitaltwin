# Baseline comparisons and local files

Production results → Compare works on the full applied horizon, independently of the other report tabs' date filters and historical scene cursor. Run to the horizon, freeze the current result, then apply different inputs. One immutable baseline survives scenario resets in this browser session. Reloading clears it; save both scenarios to reproduce the comparison later. Import and run the baseline file, freeze it, then import and run the stress file.

Only complete recorded ledgers at the horizon qualify. Horizon-reached with unfinished WIP is valid and visible; blocked, failed, cancelled, still-calculating and event-limited runs cannot be frozen or compared. Equal dates, time zone, empty initial plant, opening material lots and model/assumption versions are required. Changed calendars, staffing, orders, processing times and costs remain explicit parameter differences. The current model supports no imported initial aircraft/WIP state.

Each monthly row uses the plant's calendar month; partial first/last months are marked. Ending WIP is a point-in-time stock and must not be summed across months. Delivery counts and posted/accrued costs are period flows and reconcile across the months. Every delta is current minus baseline. Paid labor, overtime premium, issued material, carrying and lateness remain separate categories. Unfinished carrying and lateness are accrued through the cutoff, not estimates of future completion. A lower material total can reflect different or fewer kit issues; inspect output and WIP before calling it an improvement. The selected aircraft has paired station timelines on identical full-horizon scales, recorded milestone dates and a link to its current-run inspector.

Scenario JSON stores settings, seed, schema, engine, operating-assumption, scenario and cost versions. It does not store arbitrary events, scripts, external URLs, file references or an engine checkpoint. Import validates the whole file before replacing progress. Maximum UTF-8 size is 1,000,000 bytes, depth 16 and 20,000 structural values; the underlying builders enforce at most 60 orders, a 90/366-day horizon, bounded calendars/resources/stress inputs and a 250,000-event run guard. Unknown versions and extra fields are rejected without migration. No cloud storage or fetching occurs.

Results CSV contains monthly deliveries/WIP and category costs, total material units per SKU, admitted-aircraft final states, full-horizon category costs and accrued unfinished exposure. Monthly rows and full-horizon rows are alternative aggregates, not additive charges. Event CSV contains one row per event or material-issued allocation; repeated sequence numbers for a multi-lot issue mean allocations of one event, not duplicate events. Quantity is populated only for issues. UTC event times, serial, task, SKU, versions and seed retain provenance. CSV quotes delimiters/newlines and neutralizes spreadsheet formula prefixes. Save the scenario JSON alongside CSV to retain exact assumptions and reproduce output.
